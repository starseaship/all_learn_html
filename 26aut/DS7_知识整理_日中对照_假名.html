全课主线

実社会じっしゃかいでは、データ・AIが製造業せいぞうぎょう、小売業こうりぎょう、サービス業ぎょう、公共こうきょう・インフラで活用かつようされています。製品せいひんの状態じょうたいを把握はあくし、顧客こきゃくに合あうサービスや新あたらしいビジネスを生うみ出だします。

本课关注实际应用：用什么数据、解决什么问题、创造什么价值。贯穿四个行业，并延伸到共享经济、D2C 和智慧城市。

展开原讲义（P1–3）

制造业

讲义 P5 · P34

KOMTRAX：工程机械远程管理

KOMTRAXは、建設機械けんせつきかいの位置いち、稼働時間かどうじかん、燃料残量ねんりょうざんりょうなどを収集しゅうしゅうします。盗難防止とうなんぼうしから遠隔管理えんかくかんり、部品交換ぶひんこうかんや修理時期しゅうりじきの提案ていあんへとサービスが広ひろがります。

位置与设备内部数据 → 防盗、了解使用状态 → 提醒换件或维修、提供节油建议。重点是持续积累数据后，服务可以逐步扩展。

讲义 P6

＠REMOTE：打印机远程维护

リコーの＠REMOTEは、複合機ふくごうきやプリンターをインターネット経由けいゆで管理かんりします。故障こしょうの予防よぼう、自動通報じどうつうほう、トナー注文ちゅうもんの簡素化かんそかにより、停止時間ていしじかんや作業さぎょうの負担ふたんを減へらします。

从“出现问题后上门维修”转向远程掌握设备状态、及时维护。数据不仅提高效率，还能支持适合客户使用环境的机型建议。

讲义 P7

e-Palette：从出售车辆到提供移动服务

e-Paletteは、自動運転機能じどううんてんきのうを備そなえた箱型はこがたEVの構想こうそうです。自動車じどうしゃを所有しょゆうすることよりも、移動いどうをサービスとして利用りようすることを重視じゅうしします。

讲义以 2018 年公布的构想说明商业模式变化：用户购买的是移动服务，企业销售的不再只是车辆本身。

讲义 P8 · P34

JINS MEME：眼镜也是传感器

JINS MEMEはセンサーを内蔵ないぞうしたメガネで、IoTの一例いちれいです。加速度かそくど・ジャイロセンサーと眼電位がんでんいセンサーで、体からだの動うごき、まばたき、視線移動しせんいどうなどをとらえます。

传感器数据用于理解集中、疲劳、困倦和活动状态；讲义进一步展示驾驶、办公、跑步等应用扩展。注意：它是根据测量数据推断状态。

讲义 P9

Optune：个性化护肤

Optuneは、肌はだの測定結果そくていけっか、気候きこう、気分きぶんなどのデータを分析ぶんせきし、肌状態はだじょうたいに合あう美容液びようえきや乳液にゅうえきを提供ていきょうするIoTサービスでした。講義資料こうぎしりょうには、サービス終了しゅうりょうと明記めいきされています。

个人当时的皮肤与环境数据 → 分析 → 从多种组合中提供护理方案。原讲义已注明服务结束，因此应作为历史案例理解。

展开原讲义（P4–9）

零售业

讲义 P11

POS 与 ID-POS：多了“谁购买”

POSは「いつ、何なにが、何個なんこ、いくらで売うれたか」を管理かんりします。ID-POSは会員情報かいいんじょうほうとPOSデータを結むすび付つけ、「誰だれが」という情報じょうほうを加くわえます。

POS 看销售记录；ID-POS 将记录关联到会员，进一步分析最近来过、经常来、购买金额高的顾客。两者最关键的区别是能否关联顾客身份。

讲义 P12

Tesco：商品属性与顾客分群

テスコは商品しょうひんに健康けんこう、価格かかく、利便性りべんせいなどの属性ぞくせいを付つけ、購買履歴こうばいりれきから顧客こきゃくを分類ぶんるいします。店舗てんぽごとの顧客層こきゃくそうに合あわせて棚割たなわりやマーケティングを考かんがえます。

商品 DNA 指商品所反映的生活方式特征，并非生物基因。购买记录 → 健康导向、价格导向等顾客群 → 调整门店货架与营销。

讲义 P13

Amazon Go：无须排队结账

Amazon Goでは、店内てんないのセンサーが客きゃくの取とった商品しょうひんと数量すうりょうを検知けんちし、退店時たいてんじに自動じどうで決済けっさいします。レジに並ならぶ手間てまを減へらすサービスです。

入店识别 → 传感器判断拿取商品 → 离店自动结算。讲义中的门店数量是 2020 年时点数据，不能当成今天的数量。

服务业

讲义 P15

Wealthfront：机器人投顾

Wealthfrontは、家族構成かぞくこうせい、収入しゅうにゅう、投資目的とうしもくてきなどへの回答かいとうをもとに、資産運用しさんうんようのモデルを作つくるサービスとして紹介しょうかいされています。こうしたサービスをロボアドバイザリーと呼よびます。

将个人情况与投资偏好转为可分析的数据，支持个性化资产配置。这里学习的是数据应用方式，不代表收益保证或投资建议。

讲义 P16

Kabbage：多源数据评估信用

Kabbageは、銀行ぎんこう、会計かいけい、決済けっさい、EC、SNSなどのデータから、中小企業ちゅうしょうきぎょうの信用力しんようりょくを測定そくていする融資ゆうしサービスとして紹介しょうかいされています。金融きんゆうとデジタル技術ぎじゅつを結むすび付つけたビジネスがFinTechです。

并非只看传统担保，而是综合经营相关数据进行信用评价。讲义“最快 6 分钟”属于案例描述，不是当前服务承诺。

讲义 P17

Amazon Lending：销售数据成为信用依据

Amazonレンディングの事例じれいでは、出店者しゅってんしゃの売上うりあげや在庫量ざいこりょうなどの実績じっせきをもとに、信頼度しんらいどを評価ひょうかします。プラットフォームが保有ほゆうするデータを、融資ゆうしという別べつのサービスにも活用かつようしています。

电商平台掌握的经营数据能支持信用评价和融资。重点是数据的跨业务使用；讲义中的额度、利率、审批时间均按历史案例理解。

公共与基础设施

讲义 P19

智能电表与 HEMS

スマートメーターは、検針けんしんを自動化じどうかし、電気使用状況でんきしようじょうきょうを見みえる化かする電力量計でんりょくりょうけいです。HEMSは家庭かていのエネルギーを管理かんりする仕組しくみです。

智能电表负责计量和通信；HEMS 是家庭能源管理系统。数据可用于掌握用电情况、节能和供电管理。讲义中的普及完成时间是当时的预测。

讲义 P20

BRIMOS：桥梁监测

BRIMOSは、橋はしに設置せっちしたセンサーで状態じょうたいを継続的けいぞくてきに監視かんしするシステムです。災害時さいがいじの被害ひがいや劣化れっかの把握はあく、補修時ほしゅうじの品質確認ひんしつかくにんなどに役立やくだちます。

基础设施传感器 → 持续掌握状态 → 支持维护管理。讲义还列出车辆重量与超载监测，并注明车重、车型推定适用于钢桥或钢制高架桥。

讲义 P21

MaaS 与 Whim：整合多种交通

MaaSは、鉄道てつどう、バス、タクシーなどを一ひとつの移動いどうサービスとして統合とうごうする考かんがえ方かたです。Whimの事例じれいでは、現在地げんざいちと目的地もくてきちをもとに経路検索けいろけんさくや決済けっさいをまとめて行おこないます。

MaaS 不等于自动驾驶，也不只是打车软件。关键在于跨交通方式的一体化规划与使用；Whim 是讲义采用的案例。

新商业模式

讲义 P23

共享经济：闲置资源与需求匹配

シェアリングエコノミーは、遊休資産ゆうきゅうしさんをオンラインのプラットフォームで共有きょうゆうする経済けいざいです。提供ていきょうする側がわと利用りようしたい側がわをマッチングし、利用者間りようしゃかんの信頼関係しんらいかんけいが重要じゅうようになります。

闲置车辆、空间、物品或可提供的技能与时间 → 平台匹配 → 租借、买卖或交换。常见平台收入来自手续费，评价机制帮助建立信任。

讲义 P24–25

Uber 与 Airbnb：匹配的对象不同

Uberは利用者りようしゃと運転手うんてんしゅを、Airbnbは宿泊客しゅくはくきゃくと部屋へやを提供ていきょうするホストをマッチングします。講義こうぎでは、評価ひょうかやオンライン決済けっさいなどが取引とりひきを支ささえる仕組しくみとして示しめされています。

Uber 匹配出行需求与司机；Airbnb 匹配住宿需求与空间。讲义对监管、价格、保障范围的描述有时点和地区限制，不应直接当作现行规则。

讲义 P26

D2C：品牌直接面对消费者

D2CはDirect to Consumerの略りゃくで、メーカーが自社製品じしゃせいひんを消費者しょうひしゃへ直接販売ちょくせつはんばいするモデルです。SNSなどで顧客こきゃくと直接ちょくせつ対話たいわし、データを商品開発しょうひんかいはつやマーケティングに生いかします。

关键不只是网上卖货，而是品牌通过自己的渠道直接销售、交流并获得顾客反馈。减少中间环节可能带来成本优势，但“低价”不是定义本身。

讲义 P27–28

Casper：D2C 寝具案例

Casperは、自社じしゃで企画きかくした寝具しんぐをWebで直接販売ちょくせつはんばいする事例じれいです。講義こうぎでは、返品制度へんぴんせいど、レビュー、配送はいそうの工夫くふう、センサーデータを使つかった研究開発けんきゅうかいはつが紹介しょうかいされています。

把产品、购买体验、交付方式和数据反馈结合起来。讲义提到免费退货期、价格区间和传感器研究等历史措施；商业规模数字未纳入知识概要，以免将口径不明的数字当作确定结论。

讲义 P29

智慧城市：城市整体优化

スマートシティは、ICTなどを活用かつようし、都市としの課題かだいを解決かいけつして全体最適化ぜんたいさいてきかを目指めざす都市としや地区ちくです。交通こうつう、気象きしょう、健康けんこう、行政ぎょうせいなどのデータを連携れんけいさせます。

重点是跨领域协同与城市管理，不是单纯安装很多传感器。交通、能源、健康、行政等数据通过共同基础平台连接，支持可持续的城市运营。

讲义 P30–31

巴塞罗那与 Woven City

バルセロナの事例じれいでは、センサーやオープンデータを活用かつようし、駐車ちゅうしゃ、照明しょうめい、廃棄物管理はいきぶつかんりなどを改善かいぜんします。Woven Cityは、モビリティやAIなどを試ためす実証都市じっしょうとしの構想こうそうとして紹介しょうかいされています。

巴塞罗那强调开放创新与城市基础设施；Woven City 强调真实生活场景中的技术实证。此处按讲义的公布、建设计划叙述，不表示当前进度。

应用分类与落地难点

讲义 P33

四象限分类：两个维度

データ・AIの活用かつようは、「個別最適こべつさいてきか全体最適ぜんたいさいてきか」と「蓄積ちくせきしたデータかリアルタイムのデータか」で分類ぶんるいできます。誰だれのために、どのタイミングのデータを使つかうかを区別くべつします。

做分类题时先判断服务对象，再判断数据处理的时间特征。批量型侧重积累的数据，实时型侧重当下流动的数据；它们不是“先进与落后”的区别。

讲义 P34–35

数据资本主义与服务扩展

データはヒト・モノ・カネに並ならぶ企業きぎょうの資本しほんになります。蓄積ちくせきしたデータを分析ぶんせきすると、顧客こきゃくへの提案ていあん、AIの学習がくしゅう、市場動向しじょうどうこうの把握はあくに役立やくだちます。

数据可成为持续创造价值的资产。KOMTRAX 从防盗扩展到维护建议，JINS MEME 从测量扩展到多场景应用，都是同一逻辑的例子。

讲义 P36

落地的三类难点

データの活用かつようには、個人情報保護こじんじょうほうほご、複数ふくすうの組織そしきとの連携れんけい、費用対効果ひようたいこうかという課題かだいがあります。合意形成ごういけいせいやシステム接続せつぞく、データ形式けいしきの調整ちょうせいにも時間じかんと費用ひようがかかります。

①个人信息有价值，但使用需考虑保护；②跨企业、行政的数据需取得合作与共识，并解决系统和格式问题；③采集与建设成本必须与效果相称。

最容易混淆的概念

  • POS → 销售发生的时间、商品、数量、金额；ID-POS → 再加上顾客身份。
  • IoT → 设备联网并采集数据；AI → 可用于分析、识别或预测。联网本身不等于 AI。
  • MaaS → 多种交通方式作为一个服务；共享经济 → 闲置资源与需求的匹配。
  • D2C → 制造商直接面向消费者；智慧城市 → 跨领域数据支持城市整体优化。
  • 应用价值 → 效率、个性化、预测维护、新服务；实施难点 → 隐私、协作、成本。

课后自测

便利店知道卖了几盒牛奶。加上会员号之后，能多分析什么？

POS 记录商品、数量、价格和时间。ID-POS 把购买记录和会员关联起来，可以分析谁经常来、谁喜欢买某类商品。见 P11。

为什么 KOMTRAX 可以从防盗扩展到维修建议？

位置数据用于防盗。继续收集设备的稼働時間、燃料残量等数据，就能根据使用情况提醒换件或维修。见 P5、34。

手机一靠近店铺就收到优惠券，属于哪个象限？

个体最优 × 实时型。服务对象是特定顾客，触发条件是当前的位置。见 P33。

用很多车辆当前的位置和速度预测堵车，属于哪个象限？

整体最优 × 实时型。分析的是当前车流，服务的是整体交通。见 P33。

Airbnb 和 Casper 分别靠什么方式连接用户？

Airbnb 通过平台匹配有空房的房东和有住宿需求的客人。Casper 通过自己的线上渠道直接向消费者销售寝具。见 P23、25–28。
